Raster cache seam: reuse-last (render) · LRU (tune). Two adapters make it a real seam.

Problem: render exports four builders only so tune can rebuild the clip→frame chain. Tune must follow an ordering rule ("same clip's rasterizer"), and the frame-size error text is copied word for word.

Solution: make the frame pipeline a module inside render. Both the GIF encode loop and tune ask it for frames, screens and cells by output time.

  • Leverage: one interface, three callers
  • Locality: size check and resolver live in one place
  • Interface shrinks: four exports become one Build
  • Parity test checks parity by construction, without a copied oracle
  • FrameAt gets pixel tests without ffmpeg
  • No caption-font reload on every edit

schedule.New rejects a take whose beat order differs from the clock's, so agreement holds by construction.

Problem: output time is summed in four places, in two orders. Beat zooms use one order; camera moves and captions use the other. They agree only because the rig happens to run beats in storyboard order.

Solution: one clock module derived from the beats. ClipTime, beatZoomSpans and schedule's OutStart read from it.

  • Latent drift becomes a load error

After: the helpers fold into yamledit

Has · Upsert(mapping, key, value, order) · DeleteIfPresent

Problem: yamledit offers strict Set/Insert/Delete/Replace and no way to query. Tune rebuilds insert-or-update and delete-if-present on a second parse tree. Multi-step edits depend on old paths staying valid.

Solution: move query, upsert and delete-if-present into yamledit, where the source spans are already known.

  • Deletion test: the helpers are shallow
  • Upsert tested once, across block, flow and sequence-item mappings
  • Tune drops its third parse
Overlaps with #4: if typed edits land in storyboard, it becomes yamledit's only caller and needs these operations too.

6 · Resolve storyboard values once, at Parse

Worth exploring in-process
  • internal/storyboard/caption.go (validateTiming, validateColor)
  • internal/storyboard/camera.go (placeMove)
  • internal/caption/caption.go (span, parseColor)
  • internal/caption/layout.go (boxRect)

Before: validate, then every consumer resolves again

storyboard: resolves Moment, checks hex, checks bounds, discards the result
schedule.checkTiming: re-checks duration and hold
caption.span / parseColor: re-resolve, error branches that can't fire
compose.planMoves: re-resolve at
lint never sees caption overflow

After: three named tiers; consumers get resolved values

static: Parse returns Durations, RGBA, resolved starts
font-bound: caption box fits; lint runs it
take-bound: pan or zoom target is on screen
caption.New, planMoves: no timing errors

Problem: validation and resolution are separate, so caption, compose and schedule each handle errors already ruled out. Checks that need only fonts and config never run in photon lint.

Solution: Parse hands out resolved values, and the tiers get names so lint can run the font-bound one.

  • Interface narrows: no error returns that can't happen
  • Lint catches caption overflow early
  • Deletes the unreachable error-path tests
