# photon v1 — implementation plan

**Goal:** a standalone `photon` CLI that lints, records, checks and renders a terminal app's demo
clip from a `photon.yaml` and a storyboard, for any project in any language. Behaviour is ported
from the reference implementation named in `AGENTS.local.md`; every project-specific piece of it
becomes config.
**Date:** 2026-10-17
**Status:** unexecuted
**sized for:** ~200k-context host
**base:** 97b2df0
**Closes:** photon-v1
**Sources:** Notes `extension-model`, `package-layout`, `coding-conventions`, `glossary`; the
v1 issues named on each item's `**Closes:**` line; the reference implementation (`AGENTS.local.md`).

**Ratified design calls** (user, 2026-10-17, unless marked):
- **Port source:** items port from the reference implementation named in `AGENTS.local.md`; no committed file names that project, its paths, env vars, glyphs or the issue tool.
- **Areas:** nested anchors — `top`/`bottom` each `{match, pick: first|last, above|below: <anchor>, offset}`; an omitted edge is the screen edge.
- **Service ports:** `port:` fixed or `0` (photon picks a free one); every port is exported as `PHOTON_PORT_<NAME>` (upper-cased, `-`→`_`) to launch, later services, reset and `run` expects; a service also gets `PHOTON_PORT`; config `env` values expand `${PHOTON_*}`.
- **Example:** `examples/hello/{photon.yaml,hello.yaml}`, whose `setup` builds `internal/testkit/fixturetui`; serves the e2e test and the README quick start.
- **Release setup:** out of this plan.
- **Package map** (plan author, refines Note `package-layout`): `keys` (named keys, SGR mouse; leaf) · `storyboard`, `config` (+`keys`) · `take` (leaf; owns event kinds, `Box`, beat spans) · `clip` (storyboard+config loaded together, cross-checks, work dir, take path) · `target` · `terminal` · `engine` (defines its `Terminal` interface) · `service` · `check` · `rig` · `schedule` · `fonts` · `raster` · `compose` · `render` · `testkit` (test support) · `cmd/photon`.
- **Event shape** (plan author): `take.Event` is typed — `{At, Kind, Beat, Action, Form, Text, Box *Box, Cell *Point}` — never a JSON string inside a field.
- **Command dirs** (plan author): `setup`, `reset` and services run in the config file's dir; launch in `launch.dir` (relative to it, default it); `run` expects in the work dir.
- **Commands:** every command in photon.yaml and storyboards (setup, reset, launch, services, on_success, run) is one string run by `sh -c` in its dir with the PHOTON_* vars in its env; launch runs as `sh -c 'exec <cmd>'`; photon itself expands `${PHOTON_*}` only in `env` values; on Windows a `run` expect with no `sh` on PATH is a FAIL naming it.

**Standing requirements:**
- skills: coding-standards
- Tests on this host: one package at a time with `GOMEMLIMIT=2GiB`; never `-race` on `./...`.
- Ported code drops every reference-project name, env var, glyph and comment; generic names from Note `glossary` only. No file this plan adds or edits matches the `forbidden:` pattern in `AGENTS.local.md` (files that predate the plan are exempt).
- Every new package gets a `doc.go` and the one-line doc-map test (item 2).
